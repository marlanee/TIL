# 실습 5-2 Quantization
1. 학습 목표
   1. 양자화 시키면 잘 구동하는지
   2. 어떤 문제가 발생하고 해결할 수 있는지
2. 큰 모델을 작은 GPU에서 실행하고 싶다! -> 양자화
3. 핵심: 눈에 띄지 않을 정도의 손실로 최대한 압축
4. LLM의 가중치는 대부분 0 근처에 밀집된 정규분포를 따른다.
   1. 따라서 극단값은 거칠게 표현해도 품질 손실이 크지 않다!
   2. 이것이 양자화의 핵심
5. 양자화 -> 역양자화 과정에서 정보 손실(오차) 발생: 반올림 때문(`round()`)
6. 32비트와 16비트는 차이가 거의 없다 -> 16비트가 추론 기준 정밀도인 이유
7. NF4: 분포 기반 단계 배치. 오차가 더 줄어듦.(같은 4비트 균등 분할 품질 대비)
8. FP16 모델 로딩과 측정 - 기준선 확인
   1. 양자화의 효과를 제대로 평가하려면 비교 대상이 필요함
9. 측정할 때는 반드시 INT4 로딩 전에 FP16을 완전히 해제해야 한다.
10. 양자화 특징: 저장은 INT4(작게), 연산은 FP16(정밀하게)(역양자화)
    1. 학습할 때는 16비트로 정밀하게 학습하자
    2. 이런 dequantize 과정이 양자화가 항상 빨라지지 않는 이유다
11. 실제로 테스트 해보니, 모델-피크 메모리는 줄었으나 추론 시간은 늘어났다.
    1. 역양자화 오버헤드 때문이었다.
12. 양자화의 부작용 - 환경 변화 입력에서의 품질 저하 / 해결책: TTP(Test-time Prompting)
13. 어려운 문제 및 드문 패턴을 만나면 헛소리를 하기 시작한다.
    1. AI의 여유가 줄어든다. -> 추론 여유가 줄어든다.
14. 이것을, TTP로 품질 복구한다.
    1. 프롬프트만으로 품질을 복구한다!
15. 추론 여유: 불명확한 입력을 받았을 때 여러 해석 중에서 올바른 것을 골라내는 능력
16. 산술 추론 능력은 프롬프트 강화로 정확해지지 않는다.
17. TTP 템플릿 설계 원칙: 규칙을 정확하고 구체적으로 명시
    1. 강제의 형식: 답변의 통일성이 생긴다.
18. 오늘의 큰 그림!
    1. 프롬프트로 풀 수 있는 문제 -> 프롬프트 부여
    2. 프롬프트로 못 푸는 문제 -> Agent / 도구를 붙인다
    3. 지식이 부족한 문제 -> 자료를 준다
    4. 형식, 말투가 문제 -> 학습시킨다
    5. 결론: 문제에 맞는 기법을 고르는 것이 실력이다.
