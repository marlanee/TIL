# 허깅페이스를 활용한 토큰화와 임베딩
1. 허깅페이스: 거대한 AI 도서관
   1. 최신 NLP 딥러닝 기술을 누구나 쉽게 사용할 수 있도록 도와주는 플랫폼
---
1. 토큰화: 문장을 숫자로 변형하기
2. 토크나이저: 단어 사전
   1. 문장을 토큰(Token) 단위로 나누고 
3. 실습1: 토크나이저 불러오기
   1. `AutoTokenizer`, `Klue/bert-base`
4. OOV 문제 해결: 서브워드(Subword)
   1. OOV: Out-Of-Vocabulary: 사전에 없는 단어.
   2. 모델에 사전 등록이 되지 않은 단어가 들어오면 처리할 수가 없었음
   3. 이것을 해결하기 위해 서브워드(Subword) 토큰화 방식이 등장함
   4. 먼저, 단어를 더 작은 의미 단위로 분리함
   5. 그렇게 되면 처음 보는 단어라도, 작은 조각으로 조합할 수 있다는 원리임
5. 임베딩: 의미를 담은 벡터
6. 임베딩 결과 분석
   1. torch.size `shape: torch.Size([1, 25, 768])`
      1. Batch Size: 한 번에 처리한 문장의 개수
      2. Sequence Length: 문장이 토큰화 된 후의 토큰 개수
      3. Hidden Size: 하나의 문장을 표현하는 벡터의 차원
   2. 정적 임베딩 vs 문맥 임베딩(정적 임베딩 필수)
   3. 우리가 얻은 임베딩 벡터는 문장의 의미를 담고 있는 핵심 재료임.
7. 차원은 모두 4의 배수로 되어있음.
   1. 예시: 64비트 등
   2. 이유는 하드웨어 연산 최적화임.
   3. 컴퓨터는 4의 배수를 좋아함.

# 자연어처리 및 텍스트 파운데이션 모델
1. 학습 목표
   1. 텍스트 파운데이션 모델이 무엇인지 이해
2. 파운데이션 모델: 대량의 데이터를 기반으로 사전 학습된 대규모 AI 모델
3. 파운데이션 모델의 등장 이전에는 새로운 테스크를 해결하려면 해당 테스크에 대한 별도의 학습이 필요했다.
4. 파운데이션 모델의 등장 이후, 새로운 테스크는 자세한 설명(프롬프트) 입력으로 해결이 가능해졌다.
5. 파운데이션 모델의 3가지 구성요소
   1. 빅데이터: 학습 데이터가 늘어날수록 성능이 증가함
   2. 자가 학습 알고리즘: 사람이 정답을 알려줄 필요가 없다.
      1. 그렇다면 분류는? 데이터 자체만으로 AI를 학습시킨다?
      2. 사진도 인터넷에 설명이 붙어있는 것이 많아서 자체 학습이 가능하다!
   3. 어텐션 기반 트랜스포머 모델: 더 많은 데이터를 보다 잘 학습하고 이해할 수 있는 인공신경망 구조
6. 텍스트 파운데이션 모델
   1. GPT-1: 사전 학습 이후에도 파인 튜닝이 필요했다. 이유: 다음 문장 완성만 잘했지, 다른건 못했음
   2. GPT-2: 추가 학습 없이도 텍스트 지시를 통해 새로운 테스크를 "어느 정도" 수행할 수 있음을 확인
7. 텍스트 파운데이션의 특이점
   1. 규모의 법칙(Scaling Law): 더 많은 데이터, 큰 모델, 긴 학습 -> 더 좋은 성능
   2. 창발성(Emergent Property): 특정 규모를 넘어서면 갑자기 모델에서 발현되는 성질
   3. 텍스트 파운데이션 모델은, 파라미터가 7B를 넘어가서 창발성이 나타나기 시작한 언어 모델이다
8. 거대 언어 모델 예시
   1. 폐쇄형(Closed) 거대 언어 모델
      1. 예시:ChatGPT, Claude, Gemini
   2. 개방형(Open sourced) 거대 언어 모델
      1. 예시: LLaMA, Gemma, Qwen
9. 거대 언어 모델의 학습
   1. GPT-3가 거대 언어 모델의 시초임
   2. 학습 방법: 다음 토큰 예측
   3. 학습 비용: 150억원 정도로 추산
   4. 그러나 한계가 있었음.
   5. 올바르지 않은 응답을 생성하거나 유해한 응답을 생성할 수도 있었음
10. 정렬 학습(Alignment): 거대 언어 모델의 출력이 사용자의 의도와 가치를 반영하도록 하는 것
    1. 지시 학습(instruction tuning): 주어진 지시에 대해 어떤 응답이 생성되어야 하는지
    2. 선호 학습(preference learning): 상대적으로 어떤 응답이 더 선호되어야 하는지
11. 지시 학습 - 인터넷이 아닌 개발자가 직접 정제한 지시-답변 쌍으로 학습함
    1. 학습 방법 자체는 기존 언어 모델에서의 지도 추가 학습과 동일함
    2. 차이점은 각 테스크마다 별도의 지도 추가 학습 및 모델 저장이 필요 없다는 것임
    3. 해결 아이디어는 다음과 같았음
    4. 모든 자연어 테스크는 텍스트 기반 지시와 응답으로 표현할 수 있지 않을까?
    5. 학습 데이터의 다양성 증대를 위해, 각 테스크를 다양한 지시로 표현해서 학습시킴
    6. 기존 NLP 테스크 데이터를 지시 학습을 위한 데이터로 수정하여 학습 및 테스크에 활용함
    7. 학습시에 보지 못한 지시에 대한 일반화 성능 평가를 위해, 관련 없는 테스크들을 테스크에 별도로 활용함
    8. 실험 결과, 예시 없어도(0-shot) 새로운 지시에 대해 올바른 응답을 내놓는 성능이 크게 증가함
    9. 성능 향상을 위한 핵심 요소는 다음과 같았음
       1. 학습 테스크의 개수가 많아야 함
       2. 창발성을 뛰어넘은 녀석만 가능함
       3. 지시의 방법: 자연어 지시로 사람에게 대화하듯 지시하는 것이 가장 효과적
12. 지시 학습의 한계: 주어진 입력에 대해 적절한 하나의 응답이 있다고 생각함
13. 선호 학습: 다양한 응답 중 사람이 더 선호하는 응답을 생성하도록 추가학습
    1. 다양한 응답은 모델이 생성, 응답간의 선호도는 사람이 제공
    2. Chatgpt를 만들기 위한 핵심 알고리즘임
    3. 핵심 아이디어는 다음과 같음
    4. 사람의 피드백을 통한 강화학습임
    5. Chatgpt같은 생성형 AI를 사용하다 보면, 더 나은 대답을 선택하라는 문구를 본 적이 있을것임
    6. 바로 그것임
    7. 그 결과 해로운 응답과 거짓말을 덜 생성하는 유저 선호 모델이 되었음
### 디코딩 알고리즘
1. 거대 언어 모델의 자동회귀 생성(Auto-regressive Generation)
   1. 학습이 완료된 거대 언어 모델은 순차적 추론을 통한 "토큰별 생성"
   2. EOS 토큰 생성시 또는 사전에 정의된 토큰 수 도달 시 종료된다.
2. 디코딩 알고리즘 종류
   1. Greedy Decoding: 가장 확률이 높은 다음 토큰을 선택
      1. 사용하기 쉬안, 직후만 고려하여 생성 응답이 최종적으로 최선이 아닐 수 있다.
   2. Beam Search: 확률이 높은 k개(beam size)의 후보를 동시에 고려
      1. 첫 단어부터 끝 단어까지 누적 생성 확률이 가장 높은 것을 고른다.
      2. 좋은 응답 생성 확률이 높으나 계산 비용이 많이 늘어난다.
   3. Sampling: 거대 언어 모델이 제공한 확률을 기준으로 랜덤하게 생성
      1. 다양한 응답을 생성할 수 있음. 그러나 생성된 응답의 품질이 감소할 수 있음
   4. Sampling with Temperature: 하이퍼 파라미터 T를 통해 거대 언어 모델이 생성한 확률 분포를 임의로 조작
      1. 임의 조작! T가 0에 가까울수록 정답만 내뱉게 된다. 높아질수록 확률이 낮은 것도 내뱉음
   5. Top-K Sampling: 확률이 높은 K개의 토큰들 중에서만 랜덤하게 확률에 따라 샘플링
      1. 품질이 낮은 응답을 생성할 가능성을 줄일 수 있다!
   6. Top-P Sampling (or Nucleus Sampling)
      1. 현존 최고의 디코딩 알고리즘임!
      2. K를 고정하는 대신, 누적 확률(P)에 집중하여 K를 자동으로 조정
### 프롬프트 엔지니어링
1. 입력 프롬프트 = 지시 + 예시
   1. 어떻게 지시를 주는지, 어떤 예시를 보여주는지가 거대 언어 모델의 성능에 크게 영향을 미침
   2. 프롬프트 엔지니어링: 원하는 답을 얻기 위해 모델에 주어지는 입력(프롬프트)을 설계,조정하는 기법
   3. LLM에는 시스템 프롬프트가 있음
   4. 유저 쿼리와 무관하게 기본값으로 주어지는 프롬프트가 계속 질문에 들어가게 되는것임
2. Chain-of-Thought (CoT) 프롬프팅
   1. 단순히 질문과 응답만을 입력하는게 아니라, 추론 과정도 예시해 포함시켜서 질문
3. 프롬프트 엔지니어링 최신본: Skill.md
   1. 특정 task를 위해 엔지니어링된 프롬프트 
   2. 공유 가능, 사용자 정의 가능
### 거대 언어 모델의 평가와 응용
1. 평가: 구축한 시스템이 실제로 잘 동작하는지를 확인하는 단계
   1. 평가의 3요소: 목표, 평가 방법, 평가 지표
2. AI 모델의 평가: 테스트 데이터
3. 거대 언어 모델 평가의 특징
   1. 특정 테스크에서 학습된 기존 AI모델들과 달리
   2. 특정 테스크에서 학습된 기존 AI 모델들과 달리, 거대 언어 모델은 다양한 테스크에 대해 동시에 학습됨
   3. 따라서, 많은 테스크에서의 성능을 종합적으로 판단해야됨
4. 거대 언어 모델 평가 방법의 종류
   1. 정답이 정해진 경우: 예측과 정답을 비교하여 일치도를 측정
   2. 정답이 정해져 있지 않은 경우
      1. 사람이 임의 정답 작성 후 비교 -> *그 사람이 틀리면 어떡해!? gemini는 이것에 대해 답변하도록*
      2. 정답과 무관하게 생성 텍스트 자체의 품질만을 측정(PPL) / 문장이 확률적으로 얼마나 자연스러운지 측정
         1. 단순한 등장 확률이 아니라 여러 측면(창의성, 유창성, 가독성 등)을 평가하고 싶다면 전문가를 고용해 평가를 맡긴다. -> 요즘은 거대 언어 모델이 대신 평가한다.
         2. *오잉? 거대 언어 모델이 거대 언어 모델을 평가한다고? 무슨 소린지 gemini가 답변해야함*
         3. LLM-as-judge(or G-Eval): 거대 언어 모델을 통해 생성 텍스트를 평가
      3. 생성된 텍스트의 상대적 선호를 평가
         1. LMAreana로 유저들이 투표로 평가
### 거대 언어 모델의 응용 및 한계
1. 멀티모달 파운데이션 모델: 멀티모달(이미지, 비디오, 오디오) 입력, 멀티모달(오디오, 텍스트) 출력 생성
   1. 이미지를 텍스트로 바꿔 출력할 수 있게됨.
2. 합성 데이터 생성
   1. Self-instruct: 175개의 데이터를 사람에게 받아 GPT-3가 52000개의 합성 데이터를 생성함
   2. GPT-3가 만든 데이터도 좋은 학습 데이터가 되었다.
3. 거대 언어 모델의 한계: 환각(Hallucination)
   1. 사실과 다르거나, 지어낸 내용을 동일한 자신감과 유창함으로 답변함
4. 거대 언어 모델의 한계: 탈옥(Jailbreaking)
   1. 프롬프팅 엔지니어링을 통해 거대 언어 모델의 정렬을 우회할 수 있다는 것이 확인됨
5. 거대 언어 모델의 한계: AI 텍스트 검출
   1. 거대 언어 모델의 무분별한 사용이 학교 및 회사에서 여러가지 새로운 문제를 만들고 있음
   2. Q. 거대 언어 모델이 만든 텍스트를 구분 또는 탐지할 수 있을까? A. 어느정도 가능하다.
