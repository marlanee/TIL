### 상속 (Inheritance)
- 한 클래스의 속성과 메서드를 다른 클래스가 물려받는 것을 뜻함
- 상속을 사용하는 이유: 코드를 재사용하거나 수정하기 편함
```python
# 상속 예시
class Animal:
    def eat(self):
        print('먹는 중')

# Dog는 Animal을 상속 => Animal의 모든 기능을 물려받음
class Dog(Animal):   # class(class) 의 방식으로 상속한다.
    def bark(self):
        print('멍멍')

my_dog = Dog()
my_dog.bark()   # 멍멍
my_dog.eat()   # 먹는 중 / 상속 받은 함수 사용이 가능하다!
```

### 다중 상속
- 둘 이상의 상위 클래스로부터 기능을 상속받음
- 상속 받을 때 기능이 겹칠 경우, 상속 순서에 따라 결정된다. (첫번째 상속 클래스의 기능이 적용됨)
- 탐색 순서: 자식 클래스 -> 부모 클래스 (왼쪽부터)
  - 반드시 자식 클래스 먼저 확인한다! 부모는 뒷전.
```python
# 다중 상속 예시
class Person:
    def __init__(self, name):
        self.name = name

    def greeting(self):
        return f'안녕, {self.name}'

class Mom(Person):
    gene = 'XX'

    def swim(self):
        return '엄마가 수영'

class Dad(Person):
    gene = 'XY'

    def walk(self):
        return '아빠가 걷기'

class FirstChild(Dad, Mom):
    def swim(self):
        return '첫째가 수영'

    def cry(self):
        return '첫째가 응애'

baby1 = FirstChild('아가')
print(baby1.cry())  # 첫째가 응애    (자신의 메서드)
print(baby1.swim())  # 첫째가 수영   (오버라이딩한 자신의 메서드)
print(baby1.walk())  # 아빠가 걷기   (Dad에게 물려받음)
print(baby1.gene)  # XY / DAD의 클래스 변수 gene을 찾고 연산 종료.
```

### super() 함수
- MRO: 파이썬이 메서드를 찾는 순서 규칙
- super(): MRO에 따라, 부모 클래스 이름 적지 않아도 자동으로 메서드를 찾음
```python
# super를 사용했을 때
# 단일 상속일 경우
class Person:
    def __init__(self, name, age, number, email):
        self.name = name
        self.age = age
        self.number = number
        self.email = email

class Student(Person):
    def __init__(self, name, age, number, email, student_id):
        # super()를 통해 Person의 __init__ 메서드 호출
        # 결과물만 안전하게 가져왔다!
        super().__init__(name, age, number, email)
        self.student_id = student_id
```
- 다중 상속 구조일 경우: MRO에 따라 부모 뿐만 아니라 같은 계열도 찾아감
```python
# 다중 상속
class ParentA:
    def __init__(self):
        super().__init__()   # <- 이 줄이 주석 처리된 것이 이 예제의 핵심
        print(super())
        self.value_a = 'ParentA'

    def show_value(self):
        print(f'Value from ParentA: {self.value_a}')


class ParentB:
    def __init__(self):
        self.value_b = 'ParentB'

    def show_value(self):
        print(f'Value from ParentB: {self.value_b}')


class Child(ParentA, ParentB):
    def __init__(self):
        super().__init__()  # ParentA 클래스의 __init__ 메서드 호출
        self.value_c = 'Child'

    def show_value(self):
        super().show_value()  # ParentA 클래스의 show_value 메서드 호출
        print(f'Value from Child: {self.value_c}')

child = Child()
child.show_value()
"""
Value from ParentA: ParentA
Value from Child: Child
"""

print(child.value_c)  # Child
print(child.value_a)  # ParentA
print(
    child.value_b
)  # AttributeError: 'Child' object has no attribute 'value_b'
```

### 예외 처리
- 예외를 적절하게 처리할 수 있는 방법이다.
- try, except 구문을 사용해 특정 예외를 잡아낼 수 있다.
- 
```python
# try-except
try:
    result = 10 / 0
except ZeroDivisionError:
    print("0으로 나눌 수 없습니다.")   # 예외 발생시 중단 후 프린트 실행

# 재미있는 예외 처리
try:
    num = int(input('숫자입력 : '))
except ValueError:
    print('숫자가 아닙니다.')   # 사용자가 분명 숫자 말고 다른것도 입력할 것이다. 말을 안들을거야.
else:
    print("참 잘하셨습니다")
finally:
    print("당신은 결국 놀아난 것에 불과합니다.")
```
### 복수 예외 처리
```python
# 복수 예외처리
try:
    num = int(input('100을 나눌 값을 입력하시오 : '))
    print(100 / num)
except (ValueError, ZeroDivisionError):
    print('제대로 입력해주세요.')
```

### 예외 처리 주의사항
예외 처리 class들도 상속받는 구조를 갖고 있음. 그래서 주의해야 할 점이 있다. 아래와 같은 예시를 살펴보자.  

```python
# 아래와 같이 예외를 작성하면 코드는 2번째 except 절에 이후로 도달하지 못함
# ZeroDivisionError 클래스는 Exception 클래스의 하위 클래스 중 하나이므로 ZeroDivisionError를 먼저 작성해야 함
try:
    num = int(input('100으로 나눌 값을 입력하시오 : '))
    print(100 / num)
except Exception:
    print('숫자를 넣어주세요.')
# ZeroDivisionError는 Exception의 하위 클래스이므로 Exception보다 먼저 작성해야 함
except ZeroDivisionError:
    print('0으로 나눌 수 없습니다.')
except:
    print('에러가 발생하였습니다.')
```

### 예외 객체 다루기
- as 키워드
```python
my_list = []

try:
    # 빈 리스트의 1번 인덱스에 접근 => IndexError 발생
    number = my_list[1]
except IndexError as error:
    # error에는 예외 객체가 담김
    # print에서 문자열로 변환되며 실제 에러 메시지가 출력됨
    #   => 'list index out of range'
    # list index out of range가 발생했습니다.
    print(f'{error}가 발생했습니다.')
```
### EAFP & LBYL
- EAFP (try-except): 예외 처리 중심 코드 작성
  - 허락보다 용서가 쉽다.
  - 예외를 예측하기 어려울 때 유용함
- LBYL (if-else): 값 검사를 중심으로 코드 작성
  - 돌다리도 두들겨 보고 건너자.
  - 예외가 예상될 때 유용함
- 실무에서는 EAFP를 많이 사용한다고 한다...
- 지금은 LBYL 방식을 많이 사용할 수밖에 없지만 말이다.
