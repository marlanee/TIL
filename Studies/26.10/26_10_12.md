# Django

### 서론: 프레임워크 학습을 앞두고
- Django는 프레임워크 중 하나인 듯하다.
- 하루마다 진행되는 수업은 독립적이지 않고 전체의 일부이다. 놓치면 따라가기 힘듦

### Web Application (web service)
- 인터넷으로 사용자에게 소프트웨어 프로그램을 구축하는 과정

### 클라이언트와 서버
#### 웹의 동작 방식
1. 클라이언트 - 서버 구조 / 요청(client) - 응답(server) 방식으로 작동한다.
   1. 사용자가 구글.com을 입력 
2. Django는 Backend에 해당한다.

### Framework
#### Web Framework / 웹 서비스 개발에 필요한 것
- 웹 애플리케이션을 빠르게 개발할 수 있도록 도와주는 도구
- 개발에 필요한 기본 구조, 규칙, 라이브러리 등을 제공 (로그인, 회원관리, 데이터베이스, 보안 등)

#### Django Framework
- Python 기반 대표적인 웹 프레임워크
1. Django를 사용하는 이유: 다양성, 확장성, 보안, 커뮤니티 지원

### 가상 환경 (Virtual Environment)
- 하나의 컴퓨터 안에서 또 다른 독립된 파이썬 환경
- 왜 필요한가? -> 서로 다른 패키지 버전 사용을 위한 독립적인 개발 환경 조성 등

#### 가상환경 동작 방법
1. 가상 환경 생성
   1. python -m venv venv
   2. 현재 디렉토리 안에 venv라는 폴더가 생성됨
   3. venv 폴더 안에는 파이썬 실행 파일, 라이브러리 등을 담을 공간이 마련됨
   4. venv라는 이름의 가상 환경을 생성한 것
2. 가상 환경 활성화
   1. source venv/Scripts/activate
3. 가상 환경 종료
   1. deactivate

```bash
python -m venv venv
source venv/Scripts/activate
deactivate
```

### 의존성 패키지
- 하나의 프로젝트가 실행되기 위한 꼭 필요한 각각의 패키지
---
1. 패키지 목록 확인
   1. pip list
2. 의존성 설치
   1. pip install -r requirements.txt
3. 의존성 내보내기
   1. pip freeze > requirements.txt
   2. 다른 파일명으로도 가능하나, 관례적으로 requirements.txt 사용
4. 의존성 패키지 관리가 필요한 이유
   1. 환경의 통일: 버전이 다른 경우 함수명이나 동작이 달라질 수 있다
   2. 협업 효율: 프로젝트가 커질수록 사용하는 패키지의 개수도 늘어나게됨. 팀원 간 동일한 개발 환경 즉시 구축 가능

### Django 프로젝트 생성 및 서버 실행
1. Django 설치
   1. pip install django
2. 프로젝트 생성
   1. django-admin startproject firstpjt . 
   2. 의미: 장고 프로젝트를 firstpjt라는 이름으로 현재 디렉토리에 만들겠다.
3. 서버 실행
   1. python manage.py runserver    # manage.py 파일 이용

### Design Pattern
- 소프트웨어 설계에서 반복적으로 발생하는 문제를 검증하고 재사용 가능한 일반적인 해결책
---
1. MVC 디자인 패턴
   1. Model, View, Controller
2. MTV 디자인 패턴: 장고 팀에서 바꾼 디자인 패턴. Mode, Template, View

### 프로젝트와 앱
1. Django project: 애플리케이션의 집합 / DB설정, URL 연결, 전체 앱 설정 등을 처리
2. Django application: 독립적으로 작동하는 기능 단위 모듈
3. *프로젝트 안에 애플리케이션이 있다. 집합 느낌*
---
1. 앱 생성
   1. python manage.py startapp articles    # 앱의 이름은 복수형으로 지정하는 것을 권장
2. 주의사항: 반드시 앱을 생성한 후에 등록해야 함    # 명령어로 생성 후 settings.py의 INSTALLED_APPS의 맨 앞 행에 추가
---
1. 프로젝트 구조
   1. settings.py
   2. urls.py
2. 앱 구조

### 요청과 응답
1. Django와 요청 & 응답
   1. 사용자가 서버에 접속하는 과정: 요청 -> urls.py -> viesw.py -> models.py or templates -> views.py -> 응답
2. *urls.py에 path를 추가하고, views.py에 index 함수를 선언했다. 그런 과정을 실습해 보았다.*
3. Template
   1. articles 앱 폴더 안에 templates 폴더 생성 # 폴더명은 반드시 templates여야 하며 개발자가 직접 생성해야 함
   2. templates 폴더 안에 articles 폴더 생성
   3. articles 폴더 안에 템플릿 파일 생성
4. Django에서 template을 인식하는 경로 규칙
   1. app폴더 / temlates / articles / index.html
5. 데이터 흐름에 따른 코드 작성하기
   1. URLs -> Views -> Templates

### 참고
1. Django는 Full Stack framework 인가요? -> 네. 그러나 프론트엔드 쪽이 좀 미흡해요
2. render 함수
   1. request: 응답을 생성하는데 사용하는 요청 객체
   2. template_name: 템플릿 이름의 경로
   3. context: 템플릿에서 사용할 데이터
3. MTV 디자인 패턴 정리
   1. Model
   2. Template
4. Trailing Comma (후행 쉼표)
5. Django 규칙
   1. urls.py에서 각 url 문자열 경로는 반드시 '/'로 끝남
   2. views.py에서 모든 view 함수는 첫번째 인자로 요청 객체를 받음 / render(request)
   3. Django는 특정 경로에 있는 template 파일만 읽어올 수 있음
