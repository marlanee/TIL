# Web (World Wide Web)
인터넷으로 정보를 공유하는 공간  
- Web의 구성요소: HTML (구조), CSS (양식), JS (기능)
### HTML (HyperText Markyp Language)
- Hypertext: 비선형적으로 주소를 이동 가능함
- Markup Language: 데이터의 구조와 의미를 정의함. 
  - Markdown 형식이 Markup의 하위 버전임
- HTML: 컴퓨터가 이해할 수 있도록 작성하는 방식
  - 웹 브라우저가 변환을 담당함
  - F12를 누르면 나오는 괴상한 코드들이 HTML 변환 전, 원본임.
- HTML 구조: html, head, body를 가진다.
  - 우리가 보는 사이트는 body 부분이다.
  - head는 메타 데이터. 컴퓨터에게 설명하는 데이터
```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=PPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPPP, initial-scale=1.0">
  <title>Document</title>
</head>
<body>
  <P>내 페이지입니다.</P>
  <P>반갑습니다.</P>
  <!-- 나는 바보. 커피를 키보드에 쏟다니. -->
   <a href="https://www.google.com/?hl=ko">Google</a>
   <!-- 로컬 이미지 -->
   <img src="images/sample.png" alt="대체 텍스트">
   <!-- 웹에 있는 이미지 -->
   <img src="https://picsum.photos/200/300" alt="랜덤 이미지">
   <p>Hi <em>나는 바보</em></p>
   <p><strong>나는천재</strong></p>
   <p><h1>우하하</h1></p>
   <ol><li>곰</li><li>세</li><li>마</li><li>리</li></ol>
</body>
</html>
```
- 대표적인 HTML structure
  - h1~h6, strong, em, ol, li 등

### CSS (Cascading Style Sheet)
웹 페이지의 디자인과 레이아웃을 구성하는 언어  
1. 인라인 (Inline) 스타일
  - html 요소 안에 style 작성
  - 내용이 뒤로 밀려서 가독성이 떨어지는 단점이 있음
  - 그래서 안 쓰는 것을 권장함 / 내부, 외부 스타일 시트 권장
2. 내부 스타일 시트
  - head에 style 태그로 작성
3. 외부 스타일 시트
  - 별도 CSS 파일 생성 후 html link 태그로 불러오기
- 스타일 적용 우선순위는 인라인 -> 내부 -> 외부

### CSS 구문
- CSS의 요소들
  1. 선택자 (중요): 누구를 꾸밀지 지정함
  2. 선언: 어떻게 꾸밀지 명령함 / ; 을 사용해서 선언 종료
  3. 속성: 바꾸고 싶은 스타일의 종류
  4. 값: 속성에 적용할 구체적인 설정

- CSS 기본 선택자
  1. 전체 선택자 (*): html 모든요소 선택
  2. 요소 선택자: 지정한 모든 태그를 선택
  3. 클래스 선택자: ('.'(dot)): 재사용성 / 클래스를 가진 모든 요소를 선택 / 거의 다 이걸로 사용한다.
  4. 아이디 선택자 ('#'): 아이디를 가진 요소 선택 / 문서에는 고유 아이디는 하나만 있어야 한다.
  5. 속성 선택자 ('[]' (대괄호)): 몰라도 됨(?)

- 자식 결합자 (Combinators)
  1. 자식 결합자 (">"): 첫 번째 요소의 직계 자식만 선택
  2. 자손 결합자 (""(space)): 첫 번째 요소의 자손 요소들 선택

### 명시도
결과적으로 요소에 적용할 CSS 선언을 결정하기 위한 알고리즘  
명시도는 선택자들의 점수 싸움임 (가중치 계산)  
가중치가 동일할 경우 마지막 선택자가 적용됨

- 명시도가 높은 순위
  1. Importance: 초딩 태그
  2. Inline 스타일
  3. 선택자: id 선택자 > class 선택자 > 요소 선택자
  4. 소스 코드 선언 순서

### 선언
1. 속성 (Property): 스타일링 기능과 특성
2. 값 (Value): 속성의 구체적 설정

- 값의 단위 (Units)
  1. 절대 단위: px, pt, cm 등 / 다른 요소 영향 x
     1. px: 픽셀 기준 / 휴대폰-컴퓨터 등 기기에 유동적으로 적용이 안됨
  2. 상대 단위: 다른 요소(부모, 화면 표시 영역 등)의 크기에 따라 상대적으로 결정됨
     1. em: 부모 요소의 font-size를 기준으로 크기가 결정됨
     2. rem: em의 단점 극복 / 부모 요소가 아닌, 최상의 요소인 <html>을 따름 / 16px (최상위)

- 웹 사이트의 디자인은, 모든게 네모에서 시작된다. 네모에서 조각해서 다른 도형을 만든다.

### CSS Box Model
웹 페이지의 모든 HTML 요소를 감싸는 사각형 상자 모델

2. padding
3. margin
4. border

### 상속
기본적으로 CSS는 상속을 통해 부모 요소의 속성을 자식에게 상속해 재사용성을 높임  
- 텍스트 쪽은 상속이 된다.

### HTML 스타일 가이드
- 대소문자 구분: html은 대소문자를 구분하지 않지만, 소문자 사용을 강력히 권장함
- 속성 따옴표: 속상 값에는 큰 따옴표("")를 사용한다 / 약속임
- 코드 구조와 포맷팅: 
  - 일관된 들여쓰기를 사용 (보통 2칸 공백)
  - 요소는 한 줄에 하나씩
  - 같은 요소는 한 칸 들여쓰기
  - 아무 기능 없다. 사람이 보기 편하라고 약속 한 것임.
- 공백 처리: HTML은 연속된 공백을 하나로 처리함
  - 그래서 모든 것을 태그로 구분해야 함
- 에러 출력 없음: HTML은 문법 오류가 있어도 에러 메세지 출력을 안 함. 그냥 깨져서 보임. 우리가 찾아내야 함!

### CSS 스타일 가이드
- 코드 구조와 포맷팅
  - 일관된 들여쓰기 사용 (보통 2칸 공백)
  - 속성 뒤에는 콜론과 공백 넣기
  - 마지막 속성 뒤에는 세미콜론 넣기
  - 선택자와 속성은 각각 새 줄에 작성하기
- 선택자 사용 (무조건): class 선택자를 우선적으로 사용할 것
- 속성과 값: 속성과 값은 소문자로 작성, 0 값에는 단위를 붙이지 않음
- 이름 짓기 규칙: 의미가 뚜렷한 이름 사용
  - 케밥 케이스를 사용함(kebab-case)
  - 약어가 아닌 전체 단어를 사용함
- CSS 적용 스타일
  - 인라인 스타일은 되도록 사용하지 말아라.

```html
<!DOCTYPE html>
<html lang="en">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
  <style>
    .unit-parent {
      width: 100%;
      /* width: 100% */
      background-color: lightgray;
    }

    .child-percent {
      width: 50%;
      /* 부모의 400px 기준 ==> 200px */
      background-color: orange;
    }

    .child-px {
      width: 200px;
      /* 부모와 무관하게 고정 */
      background-color: skyblue;
    }
  </style>
</head>

<body>
  <div class="unit-parent">
    부모 요소 (width: 400px)
    <div class="child-percent">
      % 단위 자식 (width: 50% ==> 200px)
    </div>
    <div class="child-px">
      px 단위 자식 (width: 200px ==> 항상 200px)
    </div>
  </div>

</body>

</html>
```

### block
- block 타입의 대표: "div"
  - 다른 HTML 요소들을 그룹화하여 레이아웃을 구성하거나 스타일리을 적용할 수 있음
  - 헤더, 푸터, 사이드바 등 웹 페이지의 다양한 섹션을 구조화 하는 데 가장 많이 쓰이는 요소
- inline 타입: 문장 안의 단어처럼 흐름에 따라 자연스럽게 배치되는 요소임
  - 문장 속 단어를 형광펜으로 칠하는 것과 같다.
  - 줄을 바꾸지 않고, 텍스트의 일부에만 다른 스타일을 적용할 수 있음
  - Ex) a, img, span, strong
  - 줄 바꿈이 없다 (콘텐츠의 크기만큼만 영역을 차지한다) -> width와 height 속성을 사용할 수 없다.
  - 수직 방향 (상하): padding, margin, border가 적용되지만 다른 요소를 밀어낼 수 없다.
  - 수평 방향 (좌우): 다른 요소를 밀어낼 수 있다!
  - *인라인 이라는 뜻의 기원이 라인 안에 있다는 뜻이 아니었을까?*

### Normal flow
일반적인 흐름 또는 레이아웃을 변경하지 않은 경우 웹 페이지 요소가 배치되는 방식  

- inline-block 타입: inline과 block의 특징을 합친 타입
  - 줄 바꿈 없이, 크기 지정 가능
  - width 및 height 속성 사용 가능
  - padding, margin, border로 다른 요소 밀어내기 가능
  - *써보니까 확실히 좋음. 블럭 타입은 한 칸을 다 잡아먹고, inline은 영역이 없어서 밀어내기를 못한다. 합치면 네모난 버튼처럼 구역이 생긴다. 좋다.*

### CSS Flexbox
- 박스 표시 타입
  1. Outer display 타입: block, inline
  2. Inner displa 타입: CSS Flexbox / 박스 내부의 요소들이 어떻게 배치될지를 결정
- CSS Flexbox: 요소를 행과 열 형태로 배치하는 1차원 레이아웃 방식
  - 책장의 책들을 정리하는 것과 같음
  - 책장을 정리하는 1차원 정리 방식
- Flexbox 구성 요소
  1. main axis: 메인 축 / flex item들이 배치되는 기본 축. main start에서 시작, main end에서 끝.
  2. cross axis: 교차 축 / main axis에 수직인 축. / 교차 축 방향은 의미가 없다. / 위에서부터 아래로 진행방향
  3. flex container: `display: flex:` 혹은 `display: inline-flex;`가 설정된 부모 요소
     - 이 컨테이너의 1차 자식 요소들만 Flex item이 됨
  4. flex item: Flex Container 내부에 레이아웃 되는 항목

### Flexbox 속성
1. Flex Container 지정
  - flex item은 기본적으로 행으로 나열
2. flex-direction: 메인 축을 기준으로 함
  - flex item이 나열되는 방향을 지정
  - row (기본값): 행으로 왼쪽부터 배치
  - column: 세로 방향으로 위에서 아래로 배치
  - "reverse"로 지정하면 배치 순서가 역전됨
3. flex-wrap
  - 화면에 item이 꽉 차면 줄바꿈을 함
4. flex-justify
  - item들을 좌, 중앙, 우 방향으로 정렬함
5. align-content
  - 컨테이너에 여러 줄이 있을 때 상, 중, 하 방향으로 정렬함
6. align-items
  - 컨테이너 안에 있는 flex item 들의 교차 축 정렬 방법을 지정
7. align-self
  - 다른 속성들과 달리, 자식한테만 속성 부여
  - 한놈만 콕 찝어서 상하좌우 정렬
- 목적에 따른 속성 분류
  - 배치: flex-direction, flex-wrap
  - 공간 분배: justify-content, align-content
  - 정렬: align-items, align-self
  - justify는 주축, align은 교차 축
8. flex-grow
  - ??? 화장실 다녀옴
9. flex-basis
  - item에 기본 크기를 부여함 / 미부여시 컨텐츠 만큼의 크기만 생김

### 마진 상쇄
두 block 타입 요소의 margin top과 bottom이 만나 더 큰 margin으로 결합되는 현상. 잡아먹혀버림  
요소 간의 간격을 더 예측 가능하게 만듣기 위함임. 일관성도 유지하고. 위아래만 발생함.
